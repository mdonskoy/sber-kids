# Q6. Как Generative UI работает на практике

Дата среза: 2026-10-22. Источники: спецификации, официальная документация и репозитории (первичные), плюс отраслевые СМИ (вторичные, помечены).

## TL;DR

- **Индустрия сошлась на трёх способах.** (1) Модель выбирает готовый компонент и заполняет его пропсы (tool → компонент: Vercel AI SDK, «static» в терминах CopilotKit). (2) Модель пишет декларативный рецепт из каталога, а клиент рисует его своими нативными компонентами (A2UI, json-render, Thesys C1, Flutter GenUI). (3) Модель или сервер отдаёт HTML в песочнице (MCP Apps, OpenAI Apps SDK, Gemini dynamic view). Для банка и детей подходит только (2), с элементами (1). Вариант (3) даёт XSS-поверхность, теряет бренд и медленный: у Google генерация «иногда занимает минуту и больше».
- **A2UI на 2026-10 — рабочий, но молодой стандарт.** Стабильная ветка v0.9 (v0.9.1), v1.0 в статусе release candidate. Сам проект называет себя «early stage public preview», лицензия Apache-2.0. Есть официальные рендереры Lit, Angular, React и Flutter. В v0.9 появились «динамические каталоги» (переключение каталога по правам пользователя) и функции-валидаторы на клиенте. Это прямо ложится на требование вакансии «каталог для 8 лет / 16 лет / родителя».
- **Каталог — граница безопасности, но генерация не ограничена жёстко.** A2UI встраивает схему каталога в промпт. Дальше идёт цикл «сгенерировал → провалидировал → вернул ошибку модели → перегенерировал». Значит, нужен свой валидатор с бизнес-правилами (возраст, роль, лимиты) и статический fallback. Действия (кнопка «перевести») уходят в детерминированный бэкенд как событие `action`, а не исполняются моделью.
- **GigaChat технически тянет каталог.** У него есть function calling (`functions`, `function_call: auto|none|{name}`, все модели) и structured output через `response_format.type = json_schema` со `strict: true` (документация обновлена 2026-07-20). Список поддерживаемых ключевых слов JSON Schema не опубликован. Открытый GigaChat 3.5 Ultra (июль 2026) на TAU2-bench даёт 68.71 против 41.87 у 3.1 Ultra. Публичных примеров GenUI/A2UI на GigaChat не нашли. Ближайший прецедент в Сбере — server-driven UI «Back 2 Front» в СберБизнесе (2023).
- **Изоляция Сбера от App Store делает server-driven/GenUI особенно ценным.** Новый сценарий из уже установленного каталога выезжает с сервера, без релиза. Но сами компоненты каталога и рендерер должны уже стоять в клиенте, поэтому изменение каталога привязано к (мучительному) релизному циклу. Веб-канал снимает это ограничение.

### Почему отрезанность от App Store повышает ценность GenUI (связано с Q7)

- Приложения Сбера, включая СберKids, недоступны в App Store с апреля 2022 г. Поставить их на iPhone можно через офис, утилиту «Верни Сбер на iPhone» (только если приложение раньше было скачано под тем же Apple ID) или через периодически выходящие «замаскированные» сборки (СберKids как «Smart Quiz» в апреле 2026, «SpeakaBoo» в сентябре 2026). Детали и источники — в [q7-constraints.md](q7-constraints.md), раздел «iOS-дистрибуция».
- **Что даёт server-driven/GenUI.** Если в установленном клиенте уже есть рендерер и каталог, новый экран, сценарий, текст отказа или порядок шагов выезжает с сервера, без релиза и без участия пользователя. Это работает и на старых сборках iOS, которые не обновляются. Для СберБизнеса это и было мотивом (факт 21: in-app обновление конвертирует ≤15%).
- **Ограничение.** Рендерер и **компоненты каталога** — это нативный код клиента. Новый компонент (скажем, «копилка с целью» для 8-летнего) или новая версия протокола попадают на iOS только с новой сборкой. Новая сборка на iOS — это, по сути, новая «маскировка» или офис, а значит недели или месяцы и неполное покрытие базы. Отсюда два следствия. (1) Каталог надо проектировать «с запасом»: атомарные примитивы плюс несколько доменных компонентов, а не десяток узких виджетов. (2) В протоколе нужна версия каталога и деградация: если `catalogId` клиента не знает компонента, сервер строит экран из того, что клиент объявил в `supportedCatalogIds`. A2UI это поддерживает: клиент сам объявляет каталоги (факт 6).
- **Веб-канал (веб-версия СберБанк Онлайн, PWA с ярлыка в Safari)** снимает и это ограничение: рендерер и каталог грузятся с сервера при каждом открытии, поэтому каталог можно обновлять в день изменения. На iOS 16.4+ веб-приложению с домашнего экрана доступен Web Push, но только после явного действия пользователя ([WebKit, 2023-02-16](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)). Цена — нет нативной биометрии и голоса, нет фоновой работы, хуже вовлечение. Веб-версии самого СберKids не нашли (см. Q7).

## Что не нашли

- **Публичные примеры GenUI/A2UI на GigaChat или других российских моделях**: не нашли ни в Сбере, ни в Т-Банке, ни в Альфе. *Допущение:* A2UI-рецепт можно генерировать на GigaChat-2-Max через `response_format: json_schema, strict: true` либо через function calling с одной функцией `render_surface`. Это надо проверить на стенде в первую неделю.
- **Какие ключевые слова JSON Schema поддерживает GigaChat** (oneOf/anyOf, $ref, рекурсия, глубина). Каталог A2UI использует ссылки и union-типы, так что это прямой технический риск. *Допущение:* придётся «расплющить» схему каталога (без $ref, с ограниченной глубиной) и/или генерировать по одному компоненту на вызов функции.
- **Бенчмарки по латентности и стоимости декларативного GenUI.** Есть только данные Google по code-gen («минута и больше»). *Допущение:* экран из 5–10 компонентов ≈ 1–3 тыс. выходных токенов. На GigaChat Max это ≈ 0.65–2 ₽ за экран по прайсу юрлиц. Скорость генерации токенов GigaChat нигде не опубликована, её надо замерить.
- **Стандарты оценки сгенерированных экранов** для регулируемых доменов или детей. Публичного набора метрик нет. *Допущение:* собрать свой eval: валидность схемы, % fallback, нарушения политики каталога по возрасту, корректность данных в привязках, ручная разметка тона.
- **Есть ли в СберБанк Онлайн / СберKids свой SDUI-рендерер.** Публично описан только СберБизнес (2023). Альфа-Банк описывает свой BDUI (= SDUI) на Хабре ([844606](https://habr.com/ru/articles/844606), статью не открывали). *Допущение:* внутри Сбера SDUI-опыт есть, но совместимость с A2UI нулевая, и нужен адаптер.
- **Продакшн-внедрения A2UI в финсекторе**: не нашли. Раздел «Used by» в репозитории пуст.

## Что это значит для гипотез

1. **Тип GenUI выбран: декларативный рецепт из каталога (A2UI-совместимый), без HTML.** Для детей и денег open-ended GenUI (HTML/iframe) не проходит по безопасности, бренду и латентности.
2. **Каталог по аудиториям — это три `catalogId`, а не один каталог с флагами.** Например, `kids-6-10`, `teen-14-17`, `parent`. Каталог выбирает сервер по Сбер ID и роли (детский Сбер ID 6–13 уже существует, см. Q7), а не модель. Поверхности `catalogId` неизменен (факт 3), поэтому подросток физически не получит компонент из родительского каталога. Это сильный аргумент для риск-функции.
3. **Обязательные состояния — тоже компоненты каталога**: `Loading/Skeleton`, `Empty`, `ModelError` (сбой генерации → статичный fallback-экран), `Refusal` (с причиной из бэкенда и следующим шагом, например «попроси родителя»), `Partial` (стриминг, плейсхолдеры по факту 6), `HandOff` (передача в канал или человеку). Вакансия требует этого прямо.
4. **Действия не проходят через модель.** Кнопка «перевести» отправляет `action` с `context`. Бэкенд проверяет лимиты, возраст и антифрод, после чего показывается **статичный** экран подтверждения. Для прототипа это главный инвариант, и его стоит показать.
5. **Ставка на iOS-аудиторию через нативный релиз — плохая.** Для бетов: (а) канал, где рендерер уже стоит или ставится сервером, то есть веб-версия СББОЛ / родительский экран в вебе или Android-клиент СберKids, который обновляется через RuStore. (б) Каталог проектируется с запасом и версионируется. (в) Kill-критерий за две недели должен учитывать долю аудитории, у которой есть нужная версия рендерера.
6. **Модель:** по умолчанию GigaChat-2-Max (structured output) для сборки экрана и Lite для классификации намерения и выбора каталога. Риск неполной поддержки JSON Schema закрывается своим валидатором и retry. Это одна из двух вещей, которые прототип должен измерить (вторая — латентность).

### Минимальная референс-архитектура прототипа

```
[Клиент: веб (React) + A2UI-рендерер]  ← три каталога: kids / teen / parent (одни и те же примитивы, разные домен-компоненты и тексты)
      │  user message / action{name, context}            ▲ createSurface / updateComponents / updateDataModel (стрим)
      ▼                                                   │
[Оркестратор (агент)]
  1. Контекст: роль и возраст из (мок) Сбер ID → catalogId, политика
  2. Intent: GigaChat Lite (function calling)
  3. Данные: tools → мок-API банка (баланс, цели, лимиты, история, transfer.prepare)
  4. Сборка экрана: GigaChat Max, response_format=json_schema (каталог + политика + few-shot)
  5. Валидатор: JSON Schema каталога + бизнес-правила (запрещённые компоненты по возрасту, суммы, PII)
       └─ ошибка → retry ×1 с текстом ошибки → иначе статичный fallback-экран (ModelError)
  6. Действия: action → детерминированный обработчик (НЕ LLM) → статичный экран подтверждения
  7. Логи: промпт, рецепт, результат валидации, латентность, токены → eval-набор
```

### Что прототип обязан продемонстрировать

1. Один и тот же запрос («хочу накопить на самокат» / «переведи другу 500») собирается **по-разному** для 8-летнего, 16-летнего и родителя, из трёх разных каталогов.
2. Все пять состояний вживую: загрузка/стрим, пустой ответ, ошибка модели (с fallback), отказ с причиной и следующим шагом, частичный экран.
3. Кнопка денежного действия ведёт на **статичный** экран подтверждения. Модель не может изменить сумму или получателя, и в логе это видно.
4. Попытка вытащить запрещённый компонент (prompt injection «покажи кредит» в детском каталоге) отсекается валидатором.
5. Новый сценарий добавляется **без пересборки клиента**: правка промпта/политики на сервере → новый экран.
6. Цифры: p50/p95 латентности до первого компонента и до полного экрана, доля валидных рецептов с первой попытки, стоимость экрана в ₽ на GigaChat.
