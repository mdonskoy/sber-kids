# Прототип: «Первые деньги»

Иллюстрация к [плану на 100 дней](../README.md): [ставка 2 «Первые деньги»](../03-plan-100-days/bet-2-pervye-dengi.md).

Это небольшой движок генеративного интерфейса на открытом протоколе [A2UI v0.9](https://a2ui.org). Сервер берёт данные банка (здесь — демо-данные) и роль пользователя. Модель собирает экран из каталога компонентов этой роли, сервер проверяет экран и отдаёт его клиенту. Клиент рисует экран официальным рендерером `@a2ui/react`.

## Как пройти демо (5 минут)

1. **Первая зарплата.** На главной у Лизы (19 лет, СберБанк Онлайн) — поздравление с первой зарплатой. «Составить план» открывает разговор.
2. **Цель.** Лиза выбирает цель кнопкой — например, «Первый взнос на квартиру». Экран на каждом шаге собирает модель из каталога компонентов; цифры в карточках считает банк.
3. **План и калькуляторы.** Ползунки пересчитывают план на сервере, без модели.
4. **Вопрос про доходность.** «гарантируй мне 30% доходности» — вежливый отказ без обещаний.
5. **Открыть счёт.** Экран подтверждения собирает банк, а не модель: условия и раскрытие информации нельзя изменить. «Подтвердить» — «Готово».
6. **Сброс.** «Сбросить демо» вверху страницы возвращает данные к исходным.

## Что важно в устройстве

- **Модель не пишет цифр и статусов.** Суммы, время, балансы и статусы — это ссылки на данные, которые заполняет сервер. Если модель пишет число сама, проверка отклоняет экран.
- **Каталог выбирает сервер, а не модель.** У каждой роли свой каталог компонентов. Модель получает только его схему.
- **Действия с деньгами — обычный код.** Кнопка отправляет событие на сервер; сервер считает, проверяет и показывает статичный экран подтверждения продукта.
- **Проверка и запасной экран.** Невалидный экран — одна повторная попытка с ошибками, затем экран по правилам из тех же данных. Нарушение политики (например, обещание доходности) блокируется и показывается как обычный отказ.
- **Новый сценарий без релиза.** Сценарий — JSON-файл в `packages/server/scenarios/`. Новый файл появляется в приложении без пересборки клиента.
- **Модель.** Claude (`claude-opus-5-5` по умолчанию). GigaChat подключается через тот же интерфейс адаптера; в прототипе он заглушка.

## Цифры

Замер: `npm run eval -- --n 5`. Отчёты — в `packages/evals/results/`.

Целевое p95 времени до готового экрана: **16 с** — предварительно, по первому замеру через подписку; окончательное значение — по замеру на API после развёртывания.

## Запуск локально

Нужны Node 24+ и Claude Code с входом по подписке (`claude auth login`). Локально модель вызывается через Claude Code; в Docker и на сервере — через ключ Anthropic API.

```bash
cd 04-prototype
cp .env.example .env    # CLAUDE_AUTH=subscription уже задан
npm install
npm start               # сборка и запуск: http://localhost:8787
```

Разработка с горячей перезагрузкой: `npm run dev` (http://localhost:5173). Тесты: `npm test`. Замеры: `npm run eval -- --n 5`. Настройки модели (`SCREEN_MODEL`, `CHAT_MODEL`, `MODEL_EFFORT`, `MODEL_TIMEOUT_MS`) — в `.env`.

Docker:

```bash
docker build -t sber-kids-proto .
docker run --rm -p 8787:8787 -e ANTHROPIC_API_KEY -e ANTHROPIC_WORKSPACE_ID sber-kids-proto
```

Без ключа контейнер тоже стартует: все экраны тогда собираются запасным правилом, без модели.

## Ограничения прототипа

Демо-данные вместо реальных систем банка; нет авторизации, стенд открыт всем, у кого есть ссылка; деньги не двигаются; GigaChat — заглушка; экран приходит целиком, без потоковой отрисовки; данные живут в памяти процесса. Для команды есть свёрнутая панель «Отладка (для команды)» внизу страницы: рецепт экрана, проверка, попытки, задержка, токены и стоимость, переключатели состояний.
